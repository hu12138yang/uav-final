# 当前机载状态机（2026-10-23 同步补丁）

以项目根目录 `README.md` 为当前部署和验收入口。旧版本的飞控任务下载、机载自动解锁和 AUTO 起飞流程已替换。

```text
WAIT_KML：上电常驻等待配置路径，缺文件或坏文件继续等待
  → 文件稳定且 KML 严格解析/校验成功（打开串口前）
  → LINK：等待飞控心跳、HOME、位置
  → MISSION_UPLOAD：44 → 51/73 → 47，只上传速度和普通航点
  → WAIT_GROUND_START：由地面站解锁/起飞/定点
  → 等 RTK 固定解、校时、完整位姿覆盖与真实地图就绪
  → PRE_OFFBOARD：预发送位置目标，申请 Offboard
  → OFFBOARD_CRUISE：EGO 逐段避障，普通航段返回 KML 首点
  → HOLD(MISSION_DONE)：首点上方悬停，地面站决定落地
```

GPS 或地图/雷达失效、位姿仍可信时进入安全 HOLD；异常全部清除并稳定后丢弃旧轨迹再恢复。位置/姿态消息过期、飞控时钟异常、控制调度或串口发送失败时停止运动输出，使用飞控侧已配置和验证的 Offboard 失联处理。地面站切走 Offboard 后停止控制，不自动抢回。

`--serial` 默认观察模式：只发送心跳、提频、TIMESYNC 和 HOME 查询；不执行任务上传、切模式或运动目标。实机控制必须显式 `--enable-control`，具备实际标定外参、选定真实雷达及校时/定位/感知门槛。仿真入口和虚拟 RTK 台架已移除；离线测试夹具仅在 `BUILD_TESTING=ON` 时编译。

实机点云从 SDK2 进入有界队列；RTK/EKF 位置与姿态按采样时间对齐，在工作线程内逐点去畸变和建图。控制输出独立于建图/规划线程，以配置的 `output.setpoint_hz`（默认 20 Hz）发送。

默认接收路径为项目根目录下 `missions/mission.kml`。外部接收程序写完临时文件后原子重命名交付；程序自动加载并继续启动，不需要第二次“开始”操作。任务 READY 后锁定本次航线，不在运行中接受替换。`--prepare-only` 保留立即返回语义，`--lidar-only` 跳过 KML，纯硬件观察可用 `--no-wait-kml` 跳过默认接收路径。开机服务由 `scripts/install_boot_service.sh` 在实际机载 Linux 一次性安装。

历史辅助脚本 `scripts/hil_probe.py` 中的 mission 下载功能仍是独立协议探针，不是当前机载任务入口。
